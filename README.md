## 📚 تفاصيل الوحدات التدريبية

### 1. هندسة النظام والتبحر في سطر الأوامر (System Architecture & CLI Navigation)
* **الهدف الرئيسي للوحدة:** بنهاية هذه الوحدة، سيكون الطالب قادراً على التنقل داخل هيكلية ملفات Linux الشجرية (FHS)، وإنشاء الملفات والمجلدات وتعديلها، والبحث عن أي ملف بناءً على اسمه أو حجمه باستخدام الـ CLI حصراً وبسرعة وكفاءة.
* **المفاهيم النظرية الأساسية:**
  * **هيكل دليل ملفات Linux (FHS):** فهم أن كل شيء في Linux هو ملف (`Everything is a file`). والتعرف على المسارات الحساسة: `/etc` للإعدادات، `/var` للملفات المتغيرة (Logs)، و `/opt` للتطبيقات الخارجية.
  * **المسار المطلق مقابل النسبي (Absolute vs Relative Path):** التمييز بين تبدأ المسار من الجذر `/` أو من المجلد الحالي `.` أو المجلد الأب `..`.
* **كشاف الأوامر والأدوات (Command & Tool Index):**
  * `pwd`: طباعة مسار المجلد الحالي.
  * `ls -la`: عرض الملفات بما فيها المخفية مع تفاصيل الحجم والصلاحيات.
  * `mkdir -p`: إنشاء مجلقدات متداخلة (مثل: `mkdir -p /opt/app/src`).
  * `touch` / `rm -rf`: إنشاء ملفات فارغة، وحذف الملفات/المجلدات بشكل قسري وتكراري.
  * `find /var/log -name "*.log" -size +10M`: البحث عن ملفات السجلات الكبيرة.

* **السيناريو:** يُطلب منك كمهندس تدوين هيكلية مجلدات لتطبيق مستضاف حديثاً. قم بإنشاء المسار التالي دفعة واحدة: `/opt/production/myapp/config`. داخل مجلد `config` أنشئ ملفاً باسم `app.conf`. ابحث في دليل `/var/log` عن أي ملف ينتهي بـ `.log` لنسخه إلى مجلد تطبيقك كنسخة تجريبية.

> **الأخطاء الشائعة واستكشاف الأعطال (Troubleshooting):**
> * **المشكلة:** ظهور خطأ `No such file or directory` عند محاولة الانتقال لمسار معين.
> * **التشخيص والحل:** يقع المبتدئ في خلط بين المسار النسبي والمطلق. تأكد من إضافة `/` في البداية إذا كنت تقصد مساراً مطلقاً، أو استخدم `pwd` لمعرفة مكانك الحالي قبل كتابة المسار النسبي.

### 2. إدارة الحسابات، الصلاحيات والأمان (User Management & Permissions)
* **الهدف الرئيسي للوحدة:** بنهاية هذه الوحدة، سيتعلم الطالب كيفية تطبيق مبدأ الحد الأدنى من الصلاحيات (Principle of Least Privilege)، وإنشاء حسابات مستخدمين ومجموعات مخصصة، وضبط صلاحيات الملفات والمجلدات لضمان أمن التطبيقات في بيئة الإنتاج.
* **المفاهيم النظرية الأساسية:**
  * **نموذج الصلاحيات الثُلاثي (UGO):** توزيع الصلاحيات على المستخدم المالك (User)، المجموعة المالكية (Group)، والآخرين (Others).
  * **أنواع الصلاحيات:** القراءة (`r` = 4)، الكتابة (`w` = 2)، والتنفيذ (`x` = 1).
  * **مفهوم الـ Sudo:** التوقف عن استخدام حساب `root` مباشرة كإجراء أمني، واستخدام `sudo` لتنفيذ الأوامر الإدارية بصلاحيات مرفوعة مؤقتاً ومراقبة.
* **كشاف الأوامر والأدوات (Command & Tool Index):**
  * `useradd -m -s /bin/bash <username>`: إنشاء مستخدم جديد مع مجلد شخصي ومترجم أوامر افتراضي.
  * `groupadd <groupname>`: إنشاء مجموعة جديدة.
  * `usermod -aG <groupname> <username>`: إضافة مستخدم لمجموعة (مثل مجموعة `docker`).
  * `chmod 644 / 755`: تعديل صلاحيات الملفات والمجلدات بالأسلوب الرقمي (Octal Notation).
  * `chown user:group <file>`: تغيير ملكية الملف أو المجلد.
  * `/etc/sudoers`: الملف المسؤول عن تحديد صلاحيات الـ `sudo` (يتم تعديله حصراً عبر `visudo`).

<details>
<summary>🛠️ المعمل التطبيقي (Hands-On Lab)</summary>

* **البيئة:** خادم Ubuntu Server وهمي.
* **السيناريو:** يحتاج مهندس تطبيق الـ Web للدخول وتعديل ملفات الموقع في المسار `/var/www/html`. قم بإنشاء مستخدم باسم `developer` ومجموعة باسم `webmasters`. أضف المطور للمجموعة. قم بتغيير ملكية المجلد `/var/www/html` لتصبح تابعة للمجموعة `webmasters` واضبط الصلاحيات ليكون للمجموعة حق القراءة والكتابة، بينما بقية مستخدمي النظام لهم حق القراءة فقط (`775` للمجلدات، `664` للملفات).
</details>

> [!WARNING]
> **الأخطاء الشائعة واستكشاف الأعطال (Troubleshooting):**
> * **المشكلة:** خطأ `Permission denied` عند محاولة تشغيل سكربت أو تعديل ملف.
> * **التشخيص والحل:** تحقق من صلاحيات الملف عبر `ls -l`. إذا كان السكربت يفتقد صلاحية التنفيذ، قم بتهيئته عبر تنفيذ الأمر `chmod +x script.sh`. وإذا كان الملف محمياً، تأكد من امتلاكك لصلاحيات الـ `sudo`.

### 3. معالجة النصوص وضخ البيانات (Text Processing & Data Streams)
* **الهدف الرئيسي للوحدة:** بنهاية هذه الوحدة، سيكون الطالب قادراً على تشريح ملفات الإعدادات الكبيرة، وفلترة سجلات الأخطاء (Logs) بكفاءة عالية، وضخ مخرجات الأوامر من أمر إلى آخر لأتمتة استخراج البيانات دون فتح الملفات برمجياً.
* **المفاهيم النظرية الأساسية:**
  * **تدفقات البيانات القياسية:** الإدخل القياسي (`stdin` = 0)، الإخراج القياسي (`stdout` = 1)، والخطأ القياسي (`stderr` = 2).
  * **مفهوم الأنابيب (Pipes `|`):** تمرير مخرجات أمر ليكون مدخلاً للأمر الذي يليه.
  * **إعادة التوجيه (Redirection):** حفظ المخرجات في ملفات باستخدام `>` (مسح وكتابة) أو `>>` (إضافة في نهاية الملف).
* **كشاف الأوامر والأدوات (Command & Tool Index):**
  * `cat` / `less` / `tail -f`: استعراض الملفات، ومراقبة تحديثات السجلات لحظياً (Real-time).
  * `grep -i "error" /var/log/syslog`: البحث عن النصوص وتجاهل حالة الأحرف.
  * `awk '{print $1, $5}'`: استخراج أعمدة محددة من البيانات (ممتاز لتحليل سجلات الـ Web Server).
  * `sed 's/localhost/127.0.0.1/g' config.file`: استبدال النصوص داخل الملفات برمجياً ومباشرة.

<details>
<summary>🛠️ المعمل التطبيقي (Hands-On Lab)</summary>

* **البيئة:** خادم Ubuntu Server وهمي.
* **السيناريو:** تعرض خادم الـ Nginx لهجوم أو خلل مفاجئ. قم بكتابة أمر مركب (Pipeline) يقوم بقراءة ملف السجل المحاكي، وفلترة السطور التي تحتوي على رمز الخطأ `404` أو كلمة `CRITICAL` فقط، ثم استخراج عناوين الـ IP الخاصة بالمهاجمين وحفظها في ملف مخصص في مسار `/root/blacklisted_ips.txt`.
</details>

> [!IMPORTANT]
> **الأخطاء الشائعة واستكشاف الأعطال (Troubleshooting):**
> * **المشكلة:** اختفاء البيانات الأصلية من ملف الإعدادات المهم بعد تشغيل أمر لإضافة سطر.
> * **التشخيص والحل:** استخدام المبتدئ للرمز `>` بدلاً من `>>`. الرمز الفردي يقوم بمسح محتوى الملف بالكامل (Overwrite). الحل هو النسخ الاحتياطي دوماً قبل التعديل، والتعود على استخدام الرمز المزدوج `>>` للإضافة الآمنة (Append).

### 4. إدارة الخدمات والمراقبة (Service Management & Monitoring)
* **الهدف الرئيسي للوحدة:** بنهاية هذه الوحدة، سيمتلك الطالب القدرة الكاملة على تشغيل وإيقاف خدمات النظام وتفعيلها مع إقلاع الخادم، بالإضافة إلى فحص استهلاك الموارد (المعالج، الذاكرة، الأقراص) وتحديد العمليات (Processes) التي تسبب بطء الخادم والتعامل معها.
* **المفاهيم النظرية الأساسية:**
  * **نظام مدير النظام والخدمات (systemd):** فهم أنه المحرك الأساسي لإدارة الخدمات (Units) في توزيعات Linux الحديثة.
  * **حالات الخدمة:** تفريق الحالات بين مشغلة حالياً (`active/running`)، متوقفة (`inactive`)، أو مفعلة للعمل تلقائياً مع تشغيل الجهاز (`enabled`).
  * **إشارات النظام (Signals):** كيفية إرسال إشارات برمجية لإنهاء العمليات بشكل نظيف (`SIGTERM`) أو قسري (`SIGKILL`).
* **كشاف الأوامر والأدوات (Command & Tool Index):**
  * `systemctl [start|stop|restart|status|enable|disable] <service>`: التحكم الكامل بالخدمات.
  * `journalctl -u nginx.service -n 50 --no-pager`: عرض آخر 50 سطر من سجلات خدمة معينة لاستكشاف سبب توقفها.
  * `top` / `htop`: مراقبة استهلاك الـ CPU والـ RAM والعمليات النشطة.
  * `df -h` / `du -sh *`: فحص المساحات المتاحة في الأقراص واستهلاك المجلدات.
  * `kill -9 <PID>`: إنهاء عملية مستعصية قسرياً.

<details>
<summary>🛠️ المعمل التطبيقي (Hands-On Lab)</summary>

* **البيئة:** خادم Ubuntu Server وهمي.
* **السيناريو:** قم بتثبيت خادم ويب (مثل Nginx) عبر مدير الحزم. تعمد إحداث خطأ في ملف إعداده لجعله يفشل في التشغيل. استخدم `systemctl` لتشخيص الفشل، ثم توجه لـ `journalctl` لقراءة تفاصيل الخطأ بدقة وتصحيحه. بعد تشغيله بنجاح، تأكد من ضبطه ليعمل تلقائياً في حال إعادة تشغيل الخادم (Server Reboot).

> **الأخطاء الشائعة واستكشاف الأعطال (Troubleshooting):**
> * **المشكلة:** تشغيل أمر `systemctl` وظهور شاشة معلقة لا يمكن الخروج منها.
> * **التشخيص والحل:** يعود ذلك لفتح مخرجات السجل في أداة عرض مثل `less`. الحل هو الضغط على مفتاح `q` في لوحة المفاتيح للخروج من شاشات العرض التفاعلية في Linux.

### 5. شبكات Linux والاتصال الآمن (Linux Networking & Secure SSH)
* **الهدف الرئيسي للوحدة:** بنهاية هذه الوحدة، سيكون الطالب قادراً على فحص وتكوين إعدادات الشبكة للخادم، وتأمين منفذ الاتصال عن بعد (SSH)، وتوليد مفاتيح التشفير (SSH Keys) لتمكين الأدوات الخارجية (مثل Ansible أو Jenkins) من الدخول الآمن للخادم بدون كلمات مرور.
* **المفاهيم النظرية الأساسية:**
  * **البروتوكول الآمن (SSH):** آلية عمل تشفير المفاتيح العامة والخاصة (Asymmetric Cryptography)، حيث يتم وضع المفتاح العام (`Public Key`) على الخادم ويحتفظ المهندس بالمفتاح الخاص (`Private Key`).
  * **المنافذ (Ports):** فهم فكرة المنافذ القياسية وضرورة تغيير منفذ الـ SSH الافتراضي (`22`) لتقليل هجمات التخمين العشوائي (Brute Force).
* **كشاف الأوامر والأدوات (Command & Tool Index):**
  * `ip a` / `ip route`: فحص عناوين الشبكة وجداول التوجيه (Routing Table).
  * `ss -tunlp`: معرفة المنافذ المفتوحة حالياً والبرامج التي تستمع إليها (Listening).
  * `ssh-keygen -t ed25519`: توليد زوج مفاتيح SSH حديث وقوي الأمان.
  * `ssh-copy-id`: نسخ المفتاح العام إلى الخادم البعيد.
  * `/etc/ssh/sshd_config`: ملف إعدادات حماية سيرفر الـ SSH.

<details>
<summary>🛠️ المعمل التطبيقي (Hands-On Lab)</summary>

* **البيئة:** خادم Ubuntu Server وهمي (تفعيل خيار الشبكة Bridged أو Host-Only لتمكين الاتصال به من جهازك المضيف).
* **السيناريو:** قم بتأمين الخادم باتباع المعايير التالية:
  1. غير منفذ الـ SSH من `22` إلى منفذ مخصص مثل `2222`.
  2. امنع تسجيل الدخول المباشر لحساب الـ root (`PermitRootLogin no`).
  3. امنع تسجيل الدخول بكلمات المرور تماماً واجعل الدخول حصرياً بمفاتيح الـ SSH المعتمدة (`PasswordAuthentication no`).
  4. أعد تشغيل الخدمة واختبر الاتصال من جهازك الخاص.
</details>

> [!IMPORTANT]
> **الأخطاء الشائعة واستكشاف الأعطال (Troubleshooting):**
> * **المشكلة:** بعد تعديل الإعدادات، تم إغلاق الجلسة ولم يعد بإمكان المهندس الدخول للخادم نهائياً، وظهور خطأ `Connection refused` أو `Permission denied (publickey)`.
> * **التشخيص والحل:** القاعدة الذهبية في الـ DevOps: لا تغلق جلسة الـ SSH الحالية أبداً بعد التعديل؛ افتح نافذة ترمينال جديدة واختبر الاتصال الجديد. إذا فشل، يمكنك الإصلاح من الجلسة المفتوحة سلفاً. للتصحيح، يجب الدخول عبر الكونسول المباشر وتأكد من إضافة خيار المنفذ الجديد `-p 2222` عند الاتصال.

### 6. مقدمة الأتمتة وكتابة الـ Bash Scripts (Automation & Bash Scripting)
* **الهدف الرئيسي للوحدة:** بنهاية هذه الوحدة، سيتوج الطالب مهاراته بكتابة أول سكربت أتمتة (Bash Script) يقوم بتنفيذ مهام صيانة دورية، وفحص الشروط، ثم جدولة هذا السكربت ليعمل تلقائياً في أوقات محددة دون أي تدخل بشري مستقبلاً.
* **المفاهيم النظرية الأساسية:**
  * **مترجم الأوامر (Shebang `#!/bin/bash`):** السطر الأول الحاسم في أي سكربت لتوجيه النظام لنوع المفسر المطلوب تشغيله.
  * **البنى البرمجية:** استخدام المتغيرات والشروط وحلقات التكرار لاتخاذ القرارات وأتمتة المهام المتكررة.
  * **جدولة المهام (Cron Jobs):** آلية نظام Linux لتشغيل السكربتات والأوامر دورياً بناءً على نمط زمني محدد.
* **كشاف الأوامر والأدوات (Command & Tool Index):**
  * `$1, $2`: متغيرات الوسائط المدخلة للسكربت (Arguments).
  * `if [ -f /file ]`: التحقق من الشروط (مثل وجود ملف من عدمه).
  * `tar -czf backup.tar.gz /data`: ضغط وأرشفة المجلدات.
  * `crontab -e`: تحرير جدول المهام الدورية للمستخدم الحالي.

<details>
<summary>🛠️ المعمل التطبيقي (Hands-On Lab)</summary>

* **البيئة:** خادم Ubuntu Server وهمي.
* **السيناريو:** اكتب سكربت باسم `backup.sh` يقوم بالتالي:
  1. ينشئ مجلداً للنسخ الاحتياطي باسم `/backup` إذا لم يكن موجوداً.
  2. يأخذ مسار المجلد المراد نسخه كمدخل للسكربت (`$1`).
  3. يقوم بضغط هذا المجلد وتسمية الملف المضغوط بالتاريخ الحالي لليوم (مثال: `backup_2026-06-03.tar.gz`).
  4. اختبر السكربت يدوياً، ثم قم بجدولته عبر الـ `crontab` ليعمل تلقائياً كل يوم الساعة 2 صباحاً.

```bash
#!/bin/bash
# سكريبت الأتمتة والنسخ الاحتياطي الدوري
TARGET_DIR=$1
BACKUP_DEST="/backup"
DATE=$(date +%F)

# التحقق من أن المستخدم قام بإدخال المجلد الهدف
if [ -z "$TARGET_DIR" ]; then
    echo "Error: Please provide a directory path to backup."
    exit 1
fi

# إنشاء مجلد الحفظ إن لم يكن موجوداً
mkdir -p $BACKUP_DEST

# ضغط الملفات
tar -czf $BACKUP_DEST/backup_$DATE.tar.gz $TARGET_DIR

echo "Backup successfully created at $BACKUP_DEST/backup_$DATE.tar.gz"
